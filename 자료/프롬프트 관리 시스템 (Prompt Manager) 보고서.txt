# 📝 프롬프트 관리 시스템 (Prompt Manager) 기술 보고서

> **본 보고서는 콘솔 환경에서의 AI 프롬프트 관리 애플리케이션 개발 과정과, 파이썬 기반의 데이터 구조화 및 Git/GitHub를 활용한 버전 관리 메커니즘을 논리적으로 정리한 기술 문서입니다.**

## 1. 프로젝트 개요 및 배경 (Overview & Background)

### 1.1 개발 배경 및 필요성
AI 모델 활용도가 높아짐에 따라 자주 사용하는 프롬프트의 체계적인 관리 요구가 증가하고 있습니다. 본 프로젝트는 터미널 환경에서 프롬프트를 신속하게 추가, 검색, 분류 및 즐겨찾기할 수 있는 경량화된 콘솔 기반 파이썬 애플리케이션을 구축하는 것을 목적으로 합니다.

### 1.2 문제 정의 및 해결 방안 (Problem & Solution)
* **문제 (Problem)**: 프로그램 재실행 시 메모리(RAM)에 보관된 프롬프트 데이터가 모두 초기화되는 휘발성 문제 발생
* **해결 방안 (Solution)**: 파이썬의 `json` 내장 모듈을 도입하여, 데이터 변경 시 `prompts.json` 파일에 즉시 영구 저장(Persistence)되는 구조 설계

### 3.2 주요 기능 요구사항 (Key Features)

➕ **프롬프트 C.R.U.D (추가 및 삭제)**

 * 새로운 AI 프롬프트 등록 시 카테고리, 제목, 내용을 각각 입력받아 구조화된 데이터로 저장합니다.

 * 더 이상 필요 없는 프롬프트는 번호나 키워드로 지정하여 안전하게 삭제할 수 있습니다.

🔍 **조회 & 조건별 검색 메커니즘**

 * 전체 목록 조회: 현재 저장된 모든 프롬프트의 카테고리, 제목, 즐겨찾기 여부를 한눈에 확인합니다.

 * 카테고리 검색: 번역, 코딩, 글쓰기 등 특정 카테고리에 속한 프롬프트만 모아서 필터링합니다.

 * 키워드 검색: 제목이나 내용에 특정 단어가 포함된 프롬프트를 신속하게 검색합니다.

⭐ **즐겨찾기(Bookmark) 관리**

 * 자주 사용하는 핵심 프롬프트에 즐겨찾기(★) 상태를 지정하거나 해제할 수 있습니다.

 * 전체 목록을 뒤질 필요 없이 즐겨찾기 전용 메뉴를 통해 자주 쓰는 프롬프트만 따로 모아 빠르게 호출합니다.

💾 **JSON 기반 데이터 영구 저장**

 * 프로그램 실행 시 prompts.json 파일이 존재하는지 자동으로 확인하고 기존 데이터를 메모리로 읽어옵니다(load).

 * 프롬프트를 새로 추가, 수정, 삭제할 때마다 변경 사항이 prompts.json 파일에 즉시 업데이트되어(save), 프로그램을 종료하거나 컴퓨터를 재부팅해도 데이터가 유지됩니다.

## 4. 데이터 설계 및 저장 메커니즘 (Data Design & Persistence)

### 4.1 파이썬 `json` 내장 모듈 활용 동작 메커니즘
 본 프로그램은 메모리(RAM)의 휘발성 한계를 극복하고, 사용자가 등록한 프롬프트 데이터를 안전하게 유지하기 위해 prompts.json 파일 기반의 입출력(I/O) 시스템을 구현했습니다.
 
```text
[프로그램 실행] ➔ prompts.json 검사 ➔ 데이터 로드 (json.load) ➔ 메모리 할당 (List[Dict])
                                                                   │
[프로그램 종료/수정] ◄ prompts.json 덮어쓰기 (json.dump) ◄─────── 데이터 변경 발생
```

### 📂 프로그램 실행 시 (데이터 자동 로드 / Read)

 * 프로그램이 시작되면 파이썬 코드(main.py)가 실행 위치에 prompts.json 파일이 존재하는지 검사합니다.

 * 파일이 존재하면 json.load() 함수를 사용하여 파일 속 JSON 형식 데이터를 파이썬의 List[Dict] 구조로 변환하여 메모리에 로드합니다.

 * 만약 파일이 없거나 내용이 비어있는 경우, try-except 예외 처리를 통해 에러 발생을 막고 비어 있는 기본 리스트([])로 안전하게 초기화합니다.

### 💾 데이터 수정 및 종료 시 (데이터 즉시 반영 / Write)

* 프롬프트를 새로 추가, 삭제, 즐겨찾기 상태 변경할 때마다 json.dump() 함수를 호출합니다.

* 수정된 메모리 상의 리스트 데이터를 prompts.json 파일에 즉시 덮어쓰기(indent=4 옵션으로 가독성 확보)하여 저장을 완료합니다.

* **효과**:
 저장 버튼을 따로 누르지 않거나 프로그램을 갑작스럽게 종료하더라도, 작업 중인 데이터가 유실되지 않고 영구 보존됩니다.

### 4.2 복합 자료구조 설계 이유 (List[Dict])
**Dictionary ({}) - 객체 단일화**:
 * 프롬프트 1개가 가지는 다양한 속성(title, category, content, is_favorite)을 "키: 값" 세트로 그룹화하여 단일 객체로 의미 있게 정의합니다.

**List ([]) - 집합 관리**:
 * 이렇게 만들어진 복수의 딕셔너리 객체들을 순서대로 나열하여 전체 데이터를 인덱스 기반으로 추가, 순회, 삭제 관리합니다.

### 4.3 JSON 파일 활용의 3대 장점
🔒 **데이터 영구 보존**: 메모리(RAM) 휘발성 문제 없이 프로그램 종료 및 재부팅 후에도 데이터 유지

👁️ **높은 가독성**: 사람이 직접 메모장이나 VSCode로 열어서 읽고 수정하기 쉬운 텍스트 형식

🌐 **뛰어난 호환성**: 모든 프로그래밍 언어 및 웹/앱 환경에서 사용하는 표준 포맷이라 추후 확장 용이

### 5.1 개발 환경 & 파이썬 기초 문법
**VSCode & 개발 환경 설정**
1. **파일 작성 및 실행 방식**:
 * VSCode 좌측 탐색기에서 main.py 파일 생성
 * 터미널에서 python main.py 명령어로 콘솔 프로그램 직접 실행

2. **터미널 기반 환경 점검**:
 * **python --version**: 파이썬 3.10 이상 설치 여부 확인
 * **git --version**: Git 버전 관리 도구 설치 확인
 * **git config --list**: Git 사용자 계정(Name, Email) 정보 점검

**파이썬 핵심 기초 문법**
1. **변수 (Variable)**:
 * 사용자로부터 입력받은 제목, 카테고리, 내용 데이터를 메모리에 임시 저장
 * 예시: title = input("제목 입력: ")

2. **자료형 (Data Type)**:
 * 문자열(str), 숫자(int), 리스트(list), 딕셔너리(dict), 불리언(bool) 활용
 * 예시: "번역"(str), 1(int), True/False(bool)

3. **조건문 (if-elif-else)**:

4. **반복문 (while, for)**:
 * **while True**: 프로그램 종료(6번)를 선택할 때까지 메뉴 화면을 무한 반복 출력
 * **for prompt in prompts**: 저장된 전체 프롬프트 목록을 하나씩 순회하며 화면에 출력

5. **함수 (def) 모듈화**:
 * **load_prompts()**: JSON 파일 읽기 전용 함수
 * **save_prompts()**: JSON 파일 쓰기 전용 함수

 코드의 중복을 줄이고 기능별로 깔끔하게  분리하여 가독성 및 유지보수성 향상

**List & Dictionary 복합 구조**
1. **Dictionary ({}) 사용 이유**
 * 프롬프트 1개가 가지는 다양한 속성을 "키: 값" 세트로 그룹화
 * 예시: {"title": "번역", "category": "개발", "content": "영어로 번역해줘", "is_favorite": True}

2. **List ([]) 사용 이유**
 * 복수의 딕셔너리를 순서대로 나열하여 전체 목록(장부) 관리
 * 데이터의 추가(append), 삭제(del), 인덱스 기반 접근을 용이하게 구현

3. **최종 결합 데이터 구조**
 * [ {"title": "번역", ...}, {"title": "요약", ...}, {"title": "검토", ...} ]
 * 여러 개의 데이터(List) 안에서 각 데이터의 상세 항목(Dictionary)을 체계적으로 구조화

### 5.2 Git & GitHub 버전 관리 전략
📌 **Git 개념 및 필요성**
 * 시간순 변경 내역을 관리하는 버전 관리 시스템(VCS). 오류 발생 시 원하는 과거 상태로 돌리는 타임머신 효과 및 안전한 협업 환경 제공

📌 **핵심 명령어 요약**
1. **git init**: 현재 폴더에서 Git 버전 관리 시작
2. **git checkout**: 다른 브랜치로 이동 (-b 옵션 사용 시 새 브랜치 생성 후 이동)
3. **git clone**: GitHub 저장소 전체를 내 컴퓨터로 처음 통째로 복사

📌 개념별 상세 비교
1. **git add vs git commit**
 * **git add (장바구니 담기)**: 수정한 파일 중 이번 저장에 포함할 파일만 골라 담는 준비 단계
 * **git commit (저장 도장)**: 장바구니에 담긴 파일들을 메모와 함께 영구 저장 기록(Save Point)으로 만드는 확정 단계

2. **git push vs git pull**
 * **git push (업로드)**: 내 로컬 커밋 기록을 GitHub 원격 저장소로 밀어 올려 저장
 * **git pull (다운로드)**: GitHub 원격 저장소의 최신 변경 내역을 내 컴퓨터로 당겨와 반영

3. **git clone vs git pull**
 * **git clone**: 컴퓨터에 프로젝트가 아예 없을 때 전체를 처음 다운로드 (최초 1회)
 * **git pull**: 이미 프로젝트 폴더가 존재할 때 최신 업데이트 내용만 당겨옴
---

### 🌐 GitHub 프로젝트 업로드 3단계
1. **GitHub 웹**: 새 Repository 생성
2. **터미널 주소 연결**: `git remote add origin <저장소-URL>`
3. **코드 전송**: `git push origin main`
---

### 5.3 Branch 전략 및 기능 병합 5단계
**🛡️ Branch 사용 이유**
 * 잘 작동하는 메인 코드(main)를 안전하게 보호하고, 독립된 공간에서 팀원과 동시에 기능 개발을 진행하거나 실패한 실험 코드를 손쉽게 삭제하기 위함

```text
 [기능 브랜치 작업] ➔ [main 이동] ➔ [main pull] ➔ [merge] ➔ [push origin main]
```

1. **독립 개발 환경 구축 및 저장**
git checkout -b feature/기능명 생성 후 작업 ➔ git add . ➔ git commit -m "기능 완료"
2. **main 브랜치로 이동**: git checkout main
3. **최신 상태 동기화**: git pull origin main
4. **기능 병합**: git merge feature/기능명
5. **원격 저장소 반영**: git push origin main
---

```text
트러블슈팅: 원격 저장소 충돌 해결 및 동기화
     - 문제 상황: 원격 저장소와의 이력 불일치로 `git push` 거부 (`non-fast-forward`)
     - 1차 시도: `git pull --rebase` 진행 중 `main.py` 파일 내 `CONFLICT (modify/delete)` 발생
     - 충돌 복구: `git rebase --abort` 명령어로 rebase를 취소하고 기존 로컬 상태로 복원
     - 최종 해결: `git push origin main --force` 옵션을 통해 최신 내역 원격 반영 완료
```

## 6. 결론 및 성과 (Conclusion & Takeaways)
1. **데이터 휘발성 해결 및 서비스 연속성(Persistence) 구현**
   * **기술적 성과**:
    단순 메모리(RAM) 상에서의 데이터 처리는 프로그램 종료 시 모든 정보가 초기화되는 한계가 있었습니다. 이를 해결하기 위해 파이썬의 `json` 내장 모듈과 예외 처리(`try-except`) 구조를 결합한 파일 I/O 시스템을 설계했습니다.
   * **기대 효과**:
    프로그램 실행 시 `prompts.json`의 존재 여부를 검사하여 기존 데이터를 자동으로 불러오고(`load`), 데이터 변경(추가·삭제·즐겨찾기) 즉시 파일에 덮어쓰는(`dump`) 구조를 완성하여, 재부팅이나 예기치 못한 종료 환경에서도 데이터 손실이 없는 안정적인 서비스 연속성을 확보했습니다.

2. **도메인 특성에 최적화된 자료구조(`List[Dict]`) 설계 및 적용 능력 확보**
   * **기술적 성과**:
    개별 프롬프트 데이터가 가져야 하는 다채로운 속성(제목, 카테고리, 내용, 즐겨찾기 상태)을 `"키: 값"` 구조의 `Dictionary`로 체계화하고, 이러한 단일 객체들을 하나의 `List`에 순서대로 수집하는 복합 자료구조를 구축했습니다.
   * **기대 효과**:
    단일 객체의 세부 정보 접근성을 높이는 동시에, 전체 데이터셋에 대한 인덱스 기반의 순회, 검색, 필터링, 삭제 동작의 처리 효율성을 극대화했습니다. 이는 향후 RDBMS(관계형 데이터베이스)나 NoSQL 문법을 접할 때 원활히 적응할 수 있는 구조적 데이터 관리 역량을 다지는 계기가 되었습니다.

3. **엔드투엔드(End-to-End) 소프트웨어 개발 및 버전 관리 프로세스 습득**
   * **기술적 성과**:
    단순 코드 작성을 넘어 VSCode 개발 환경 구성부터 CLI 기반의 Git 버전 관리, GitHub 원격 저장소 연동까지의 프로그래밍 전 수명 주기(Lifecycle)를 직접 경험했습니다. 특히 `main` 브랜치의 안정성을 보장하기 위해 `feature/*` 기능 브랜치 생성, 로컬 커밋, 동기화(`pull`), 병합(`merge`), 원격 업로드(`push`)로 이어지는 표준 5단계 브랜치 전략을 체득했습니다.
   * **기대 효과**:
    코드 수정 시 발생할 수 있는 오류를 이전 시점(Save Point)으로 복구하는 타임머신 메커니즘을 이해하고, 추후 다수의 인원이 참여하는 대규모 팀 프로젝트에서도 원본 코드를 안전하게 보호하며 협업할 수 있는 실무 기준의 기술적 기틀을 마련했습니다.
